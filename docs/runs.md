# 抓取记录

这里放"跑过什么、结果如何"的实测数据。README 只留结论，细节留在这里。
两条记录都来自 2026-10-09 的两次真实抓取，用的是仓库自带的配置。

## 1. 初版试跑：五站点，不限定范围

配置 `config.multisite.toml`（`max_pages = 1500`，`max_pages_per_host = 250`，
延迟 0.5s），种子见 `resources/seeds.multisite.txt`。

共有 1500 页、47487 词条。不限定范围时爬虫会跟随链接走出种子站点，实测走到了
学校新闻网、学校主页，甚至一个校内私有地址。

这次跑暴露了两个问题，促成了后来的两处修复：

- **站点被饿死**：总预算 1500 而六个种子站点，先被处理的站点把预算吃满，
  排在后面的统计学院只抓到首页一页。原因是把单站预算当成了"配额"，
  实际它是"上限"。结论与修复见 [decisions.md](decisions.md) 的 D20。
- **预算口径按 scheme + host 分桶**：同一站点的 http 与 https 被视为两个 host，
  各拿一份预算，单站上限形同虚设。修复见 D22。

顺带一提，`info.ruc.edu.cn` 在该配置的 0.5s 间隔下 robots.txt 返回 403，
抓取器按"不允许"跳过——真实验证了三态判定里的 `unavailable` 分支。

## 3. 已知边界

以下都是取舍，不是待修的缺陷。

- **站点数超过总预算时仍会有站点抓不到**：把 `max_pages` 提到"站点数 × 单站预算"
  以上才能覆盖全部站点（初版试跑的教训）。
- **同一内容可能被存两次**：部分站点在 http 与 https 上提供相同页面且不做重定向，
  两个 URL 得到不同主键。索引阶段按内容哈希去重（默认开启，可关），
  这次因此少收 1273 篇重复文档。
- **无产出上限的 CMS 会浪费预算**：化院附属站有大量 `citationstylelanguage/get/*`
  形式的导引链接，被单站预算挡住了大部分。
- **抓取务必跑到正常结束**：被强杀时 zip 的中央目录没写完，整个归档不可读。
  `reader` 会返回空而不是报错，但那一轮数据只能丢弃（见 [decisions.md](decisions.md) D25）。
- **索引体积与查询速度是一对权衡**：`term_offsets.json`（1.8 MB）换来两个数量级的
  查询提速，偏移表本身按字节累加，因此读写两端都必须用二进制模式（D24）。

归档材料 `archive/` 保留在仓库内是为了出题与评审追溯，任何代码都不导入它，
细节见 [../archive/README.md](../archive/README.md)。
